## 蒸馏目标

把五份已批准的单人能力档案抽象为一个可审计、可组合、按形式启用的 Showrunner 判断系统：从故事目的与人物欲望出发，经场景/系统因果、连续剧容量、长篇规划和生产现实，输出可执行的选择、状态、交接、诊断与修正。该目标只提取方法接口，不创建最终 Skill，不模仿任何创作者。

## 核心判断原则

1. 先判断故事目的、主题论断和形式容量，再决定是否扩展为连续剧、群像或制度系统。
2. 让人物的欲望、约束和主动选择产生可追踪后果；后果更新下一轮选择、关系、资源、责任或系统状态。
3. 场景现实、机构现实、复杂信息和长期后果分层检查，不把“现实”偷换成绝对写实。
4. 终点锁定为目标状态与必要条件，路径保持可重破；续航必须来自可解释的变化状态，不来自机械反转。
5. 制作限制先经过创意功能分析，再选择替代执行；任何综合规则都保留五份来源与 Studio 自有协议的边界。

## 共识规则

以下是五份档案在方法接口层的 A 类共识，均为 `SYNTHESIZED INFERENCE｜CROSS-DISTILLATION`：

1. 结构从 premise、人物欲望/状态、选择、压力和后果生成，不从页码、固定 beat 或“需要一个反转”倒推。
2. 关键选择不能无解释重置；至少一项关系、信息、资源、责任、权限、风险、目标或系统状态要改变。
3. 世界、关系或制度必须对行为作出可解释回应；随机事件可扰动，但不能代替主要责任链。
4. 证据、综合推断和 Studio 自有规则必须分层标记，不把作品表层、题材或人格当方法。
5. 每个有效接口都要形成输入→判断→决策→输出，并允许新证据、表演、事实或制作输入触发重破。

## 互补能力

- CM 的主题/人物论断 → VG 的选择后果：把“关于什么”变成可观察行动。
- VG 的后果状态 → SR 的 Series/EP02：让人物因果支持多集容量，而非外部危机续命。
- SR 的 engine → TG 的 destination/module：防止续航变拖延，也防止终点锁死路径。
- TG 的局部 Reality State → DS 的 Institution/System State：先验证一个人能否这样做，再验证系统如何回流。
- DS 的机构压力 → CM 的主题位置/行动证明：系统不依赖主角运行，但不抹掉人物主动性。
- 五人的戏剧功能 → TG 的 Production Reality 与 Studio 顺序：保留功能后寻找替代执行。

## 重复能力与去重结果

1. “状态变化”在 CM/VG/SR/TG/DS 中分别是人物、后果、集间、场景和系统层；去重为“按层记录状态，不跨层抹平”。
2. “因果后果”去重为局部 Choice→Consequence 与系统长期 Distributed Causality 两层；不把系统因果写成无人物责任，也不强迫立即回报。
3. “现实回应”去重为 TG 的场景 Reality Gate 与 DS 的 Institution/Incentive Gate；二者相接但不等同写实主义。
4. “room break”去重为共同输入→异议→候选→筛选→交接→复盘，不规定房间人数、卡片形状或固定天数。
5. Continuing Drive 的 SR/VG 重复去重为“状态/后果驱动的可解释下一步”，分别保留格式容量和人物责任检查。

## 条件性张力

- **续航 vs 自然终点（D）**：连续剧才启用 SR Engine；若删除一次性开场后没有可再生选择回路，缩小为电影/限定剧，不为集数扩容。
- **方向 vs 路径开放（D）**：TG/CM 锁阶段目标状态和因果条件，VG/SR 保留中间改道；新输入改变可信选择时重破并记录。
- **内在变化 vs 外部系统推进（D）**：CM 证明人物行动，DS 允许世界问题不被英雄解决；分别写人物可改变变量与系统持续变量。
- **即时回报 vs 延迟后果（D）**：VG 保持责任可追，DS 允许立即/短期/长期/潜伏时间窗；重大后果必须有中介，不必下一场报应。
- **复杂性 vs 可追踪（D）**：TG/DS 保留复杂信息和多方位置，但按观众当前任务分层，不把混乱当深度。
- **制作压缩 vs 创意完整（D）**：成本触发替代执行，只有保留 Essential Dramatic Function 才压缩。

## 真冲突

当前五份批准档案没有满足 E 类全部条件的真冲突：不存在同一项目、同一阶段、同一输入上互相否定且无法用形式、层级或条件协调的硬约束。此结论不抹去张力；若未来出现“必须完全预锁过程”与“必须完全开放路径”等同层硬冲突，按下一节保留两端、记录选择，不把任何一端伪写成共识。

## 冲突决策机制

对所有 D 张力和潜在 E 使用 `CONTEXT → QUESTION → OPTION A/B → TRADEOFF → DECISION CONDITION → DECISION → OUTPUT → REVIEW`：

1. `CONTEXT` 写形式、阶段、输入、已锁状态、制作边界；
2. `QUESTION` 只问一个可决策问题；
3. `OPTION A/B` 给出不同可执行路径，可增加“改变形式/暂停重定向”；
4. `TRADEOFF` 记录戏剧功能、人物/主题/因果/信息/制作代价；
5. `DECISION CONDITION` 使用可观察门槛，如删除开场后是否仍有选择回路、压缩是否删除不可替代权力关系；
6. `DECISION` 按层级和规则优先级选择并保留未选项；
7. `OUTPUT` 生成 Purpose/Engine/State/Module/Alternate Execution 等工件；
8. `REVIEW` 新证据、反馈或制作变化改变条件时重新进入协议。

指定交叉接口：

- **CM×VG**：CM 提供主题/误认与行动证明，VG 提供选择→后果；不要求每场都成长或升级。
- **VG×SR**：VG 的后果链供给 SR 的多集 engine；继续观看来自状态变化，不来自强行危机。
- **SR×TG**：SR 的续航受 TG 的终点、模块和现实门约束；避免 engine 空转。
- **TG×DS**：TG 先检查场景权限、空间、信息和回应；DS 再检查机构、激励、系统持续；分层而非合并成写实。
- **CM×DS**：人物变化不等于解决世界问题；系统持续不等于人物没有主动性。
- **Production×Quality**：始终执行 `Creative Intent → Essential Dramatic Function → Production Cost Driver → Alternative Execution → Scope Decision`。

## Showrunner 决策层级

这是 `AI FILM STUDIO SYNTHESIS` 的审计顺序，不是五位创作者的原生分类：

1. **L1 Story Purpose/Format**：premise、central argument、自然终点和形式容量；输出 Purpose/Format Note。
2. **L2 Character Engine**：欲望、误认/恐惧、关系位置、可选项及可信选择；输出 Character State Card。
3. **L3 World/System Engine**：按题材需要研究、机构、激励、权限、资源和无主角运行；输出最小 World/Institution Map。
4. **L4 Causal Story Engine**：Choice→Consequence→Updated State→Next Choice，并连接主题、责任、系统；输出 Causal Ledger。
5. **L5 Series/Episode Engine**：供给源、Why EP02、本集问题与季目标状态；输出 Engine Map/State Map。
6. **L6 Longform Planning**：Destination、阶段局部问题、模块出口、遗留压力、可变路径；输出 Destination Card/Module Handoff。
7. **L7 Production Reality**：成本驱动、必须保留功能、替代执行、新风险；输出 Alternate Execution/Scope Decision。
8. **L8 Diagnosis/Rewrite/Recovery**：定位最早失效层后回到最后有效状态重写，不用更大反转遮盖。

L3、L5、L6 可按形式标记 `N/A by format`，不能误当失败。上层未通过时，不能用下层 cliffhanger、低成本或强行反转补洞。

## 规则优先级

### HARD CONSTRAINT

1. 关键主链必须能解释 `选择/不作为→后果→更新状态→下一选择`；
2. 关键行为需有足够欲望、信息、权限/资源、时间和现实回应；随机起点之后仍需人物回应链；
3. 长篇/制度性项目中会改变选择成本的状态不得无解释重置；
4. 高成本创意未通过 Studio 顺序不得仅以成本或 AI 能力删除；
5. 证据、综合推断和 Studio 规则必须保留 provenance。

### DEFAULT HEURISTIC

1. 先更新状态，再问下一步，不先指定反转；
2. 用 State Ledger、Engine Map、Destination Card、Module Handoff 减少 room 记忆丢失；
3. 先用目标、行动和后果承载复杂信息，再决定解释与留白；
4. 为后果标立即/短期/长期/潜伏时间窗；
5. 为 room 保留候选、异议和可交接输出。

### CONDITIONAL METHOD

1. 连续剧/长篇且有可再生回路时启用 Series Engine；
2. 只有多方独立利益、信息、资源或因果功能会改变故事时启用 Institution/Ensemble/World Without Protagonist；
3. 只有模块有局部问题、状态变化和交接压力时拆 block/chapter/phase；
4. 只有选择空间、代价、关系/资源或价值冲突显著改变时称为升级；
5. 只有压缩仍保留 Essential Dramatic Function 时启用 Scope Compression。

### OPTIONAL TOOL

State Ledger、Engine Map、Destination Card、Reality State Card、Institution Map、Consequence Horizon、Ensemble Function Audit、Room Challenge Pass、Research Ledger、Alternate Execution 表都是可选工具，不是价值本身，不要求每个项目全部建立。

## AI Film Studio 自有综合规则

以下 13 条是五份档案经交叉去重、层级化与管线审核后形成的 Studio 规则，不归因给任何一位创作者：

1. **Purpose before expansion**：先判故事目的、主题、自然终点和形式容量，再扩展多集、多线或制度系统。
2. **State before event**：主要推进先登记人物/关系/信息/资源/责任/系统状态，再提出事件候选。
3. **Choice carries forward**：主链选择或不作为必须改变下一轮选择集；修复、观察、准备、兑现和收束段可存在。
4. **Cause is layered**：场景用 Entry→Event/Choice→Exit，跨场景用 Choice→Consequence→Next Cause，制度故事再接 Distributed Causality→System State。
5. **Engine must earn duration**：续航来自欲望、关系、职责、资源、信息或压力状态，不来自囤秘密、外来事故或平台集数。
6. **Destination is a direction**：锁阶段目的和必要因果条件，允许中间路径改道并记录。
7. **Upgrade is conditional**：升级只有在选择空间、代价、关系/资源、价值冲突或系统压力改变时成立。
8. **Reality is responsive, not documentary**：检查权限、时间、空间、资源和回应；不禁绝巧合、戏剧化或错误，只拒绝无路径无后果的强行发生。
9. **System serves causality**：只有会改变人物选择或后果的制度、研究和世界信息进入戏剧；人物仍有欲望、拒绝、误判与责任。
10. **Compress function, not meaning**：压缩昂贵外壳，不删除不可替代的主题、关系、因果、危险、系统摩擦或世界尺度功能。
11. **Conflict is a logged decision**：用冲突协议保存未选项与复查条件，不以模糊折中抹平差异。
12. **Diagnose before intensify**：先定位链断裂、人物失真、信息混乱、系统重置、续航耗竭或制作冲突，不用死亡/反转/规模遮盖。
13. **Provenance survives synthesis**：每条规则注明来源档案与证据层级，跨人归纳和 Studio 新规分开标记。

- 不继承五人任何具体作品、角色、题材外壳、机构模板、对白、视觉设计、节奏偏好或创作人格。

## 可 Skill 化规则

1. `HARD CONSTRAINT`：关键因果链必须能写成 `Choice/Non-choice → Consequence → Updated State → Next Choice`。
2. `HARD CONSTRAINT`：关键行为需要欲望、信息、权限/资源、时间与现实回应；随机起点不能跳过人物责任链。
3. `HARD CONSTRAINT`：长篇/制度性故事的选择成本状态不得无解释重置。

5. `CONDITIONAL METHOD`：仅在形式与供给源通过门槛时启用 Series/Episode/Institution/Ensemble/Module 方法。
6. `CONDITIONAL METHOD`：只在替代执行保留 Essential Dramatic Function 时压缩生产范围。

## 诊断问题

1. 删除一次性开场后，是否仍有角色—压力—选择回路？
2. 当前故事目的、主题论断和自然终点是什么？形式容量匹配吗？
3. 人物想要、害怕、误认什么？此刻有哪些可信选项及拒绝成本？
4. 选择后谁获得/失去信息、关系、资源、权限、责任或声誉？
5. 关键行为的信息、权限、时间、空间和组织回应路径是什么？
6. 机构正式目标与实际激励有何偏移？人物仍保留怎样的主动判断？
7. 移除主角后，相关世界在指定时间窗仍会发生什么？
8. 每个重要人物是否有不可替代的系统、信息、关系或因果功能？
9. 本集/本模块的局部问题、状态变化、遗留压力和交接物是什么？
10. 继续观看来自可解释后果还是扣牌、事故或更大声响？
11. 复杂信息的持有者、获取路径、当前任务和回报是什么？
12. 研究事实改变了谁的目标、权限、风险或选择？
13. 后果是立即、短期、长期还是潜伏？中介机制在哪里？
14. 终点是目标状态还是锁死的事件表？新输入怎样合法改道？
15. 制作压缩保留了哪些核心戏剧功能？新风险是什么？
16. 当前问题属于哪个层级？是否用下层技巧掩盖上层失效？

## 失败模式

|失败模式|信号|修正|
|---|---|---|
|Premise冒充Engine|只能说开场，答不出下一选择|做删除开场后的引擎门，必要时缩小形式|
|主题口号化|人物不作选择，主题只在对白|回到误认、选项、行动和后果|
|外部事件续命|每集事故重启、状态不变|把事件接回人物回应和责任链|
|假升级/假cliffhanger|更大但不改变选择集|允许兑现、修复、等待、安静段|
|系统木偶|制度替人物决定一切|补欲望、拒绝、误判和个人代价|
|主角停摆世界|主角离场世界暂停|补最小必要系统持续路径|
|群像堆人数|角色无独立功能|合并并记录损失，不按人数配额|
|复杂等于混乱|名词多、观众不知目标|按当前任务分层信息|
|终点锁死/空缺|要么事件表僵化，要么无方向扩写|锁目标状态/条件，开放中间路径|
|现实主义禁令|禁止巧合、压缩或异常选择|要求路径与回应，不禁戏剧化|
|制作先删创意|太贵/AI不会即删除|执行五段生产顺序和替代方案|
|随机文件神谕|偶然拿到完整答案|改为权限路径、多源拼图或不完整线索|

## 修正方法

1. `HARD CONSTRAINT`：重做 Purpose/Format 与 Character State，写出形式、主题、欲望、误认和可选项。
2. `HARD CONSTRAINT`：为关键行为补信息、权限、时间、资源、空间和组织回应链。
3. `DEFAULT HEURISTIC`：建立 Choice→Consequence→Updated State→Next Choice，并区分人物、场景、集间和系统层。
4. `CONDITIONAL METHOD`：按引擎耗竭信号决定增加供给、合并支线、重发明下一阶段或承认自然终点。
5. `CONDITIONAL METHOD`：把终点改成目标状态和因果条件，允许新证据触发有记录的改道。
6. `DEFAULT HEURISTIC`：将复杂事实改写成持有者、目标、障碍、选择和后果；无戏剧功能资料留在研究账本。
7. `CONDITIONAL METHOD`：为群像/制度故事建立最小功能地图；合并前记录失去的权力和因果差异。
8. `AI FILM STUDIO SYNTHESIS｜HARD CONSTRAINT`：高成本段先走 Creative Intent→Essential Dramatic Function→Cost Driver→Alternative Execution→Scope Decision。
9. `AI FILM STUDIO SYNTHESIS｜DEFAULT HEURISTIC`：冲突和返工回到最早失效层，保留未选方案与复查条件。

## 综合干跑

测试故事为原创“楼下的空房”：普通社区物业经理林岚发现五年间许多老住户搬离，表面理由分别是家庭、医疗、退休或卖房，逐步发现城市更新、房地产融资、照护机构、家庭债务和房价的交互压力。该故事不发展为正式项目。

|检验|结果|
|---|---|
|1 Story Purpose|通过：主题问题是个体选择如何被制度和家庭成本塑形；不先指定反转。|
|2 Character Engine|通过：保住工作/社区稳定的欲望与“个案修补即可解决”的误认逼出公开风险、越权或沉默选择。|
|3 World Engine|通过：移除林岚后融资、物业预算、护理排队、家庭债务、规划程序仍运行；只测住宅/照护/金融/更新边界。|
|4 Causal Engine|通过：维修记录→物业回应→护理/家庭选择→公开记录→议价与权限变化；每节点有责任与受益者。|
|5 Series Engine|通过：维修、租约、预算、转介、规划和成交等重复入口与变化状态配对，不是每集一个老人。|
|6 Episode Engine|通过：居民记录、护理接口、融资/更新文件三种单集来源；单线、修复和等待段可成立。|
|7 Destination Awareness|通过：阶段终点是可核验搬离—服务—融资—更新时间线及林岚的责任选择；中间路径开放。|
|8 Information Management|通过：公开理由/职责为当前任务，权限路径取得护理资格/融资期限/维修降级，延迟信息必须有回报。|
|9 Ensemble Function|通过：20个角色按不可替代功能压为8个叙事位置，合并损失可追。|
|10 Production Reality|通过：18地点压为6个可复用空间；保留社区公共压力、制度接口和城市尺度，记录信息密度/空间重复新风险。|
|11 Continuing Drive|通过：权限收紧、承诺、记录、信任、维修排序等状态差驱动下一步，无需大cliffhanger。|
|12 System Persistence|通过：预算、声誉、公开记录、融资期限、护理等待、规划程序、债务、联盟跨阶段继承，不无痕重置。|
|13 Rewrite Test|通过：垃圾桶捡完整阴谋文件被诊断为无权限跳跃、单一幕后黑手和后续选择耗竭；改用权限申请、多源拼图、不完整有意丢弃或合法公开材料四路修正。|

最小回路：`Research/现实依赖→Institution/Incentive→人物欲望/约束→可解释选择→立即或延迟后果→人物/关系/系统状态更新→下一阶段问题`。随机扰动、明确恶意者、安静段、单线集和有限形式均通过边界测试，但不能跳过回应、权限路径和后果。

## 反机械化测试

|压力指令|综合判断|
|---|---|
|每集增加大反转|拒绝硬化；用状态差和人物必须回应的问题，大小不是标准。|
|人物每集成长|拒绝配额；人物可反复、修复、维持误认，变化须由选择证明。|
|AI做不了群像就全删|拒绝粗暴删除；先做功能审计、合并和范围压缩，记录损失。|
|真实性禁止戏剧压缩|拒绝绝对写实；保留机制、权限、时间与后果，压缩外壳并标新风险。|
|系统故事不能有反派|拒绝绝对禁止；允许恶意节点，但只承担链条一段，不替系统解释全部结果。|
|留存就突然杀人|拒绝单独授权；高强度事件须有现实路径、人物回应和后果状态。|

六项均通过，且未把“随机不可用”“每集升级”“每场选择”“每季解决”“完整社会模拟”“低成本优先”写成硬约束。
