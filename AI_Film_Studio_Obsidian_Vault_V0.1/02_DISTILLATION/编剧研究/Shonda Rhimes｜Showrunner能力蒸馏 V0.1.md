# Shonda Rhimes｜Showrunner 能力蒸馏 V0.1

> 本稿是女娲 `huashu-nuwa` 流程在 AI Film Studio 发布边界内的首轮方法论蒸馏：证据工作区在 `runtime/_STAGING/_research/Shonda_Rhimes_V0.1/`，本稿仍在审核中，尚未进入 Obsidian 正式区。
>
> 术语边界：`SOURCE-SUPPORTED` 表示下列编号来源可直接支持的、不过度扩写的主张；`SYNTHESIZED INFERENCE` 表示根据多份来源为本项目转译的可执行判断，绝不是 Shonda Rhimes 的逐字原话或专有公式。

## 蒸馏目标

把本轮对象的可核验经验转译为中性的 **Series Engine（连续剧发动机）**：判断一个构想是否能在 EP01 之后，持续从人物、关系、职责、制度／环境与未决状态中产生值得观看的选择和变化。

本稿不是人物介绍、作品复盘或风格模仿。它不继承任何既有剧集的剧情、角色、题材、台词、节奏或视觉表达；只提供 showrunner 在格式选择、pilot、episode、season 和 writers' room 中可执行的判断回路。

## 核心判断原则

### 1. 先区分 Premise 与 Series Engine

- **硬约束｜SYNTHESIZED INFERENCE｜SHR-01、SHR-02、SHR-04、SHR-05：** `Premise` 说明观众为什么会想看初始世界、人物或异常事件；`Series Engine` 还必须说明：异常事件之后，哪些人物欲望、关系、职责、组织流程或未决压力会反复迫使新的选择，并改变下一轮的状态。
- **诊断：** 去掉 pilot 的一次性触发事件后，是否仍能说清“谁在什么约束下必须继续行动，以及该行动为何会改变关系、责任、资源、信息或目标”？说不清时，项目可能只有 premise 或有限故事，而非可续的 series。
- **边界：** 可续不等于必须无限续订；电影、限定剧、短剧和连续剧的发动机尺度不同。Rhimes 对“点子终点”的公开讨论支持先做形式判断，但不支持“电视必须永不结束”的误读。【SHR-01】

### 2. 续航由可变化状态支撑，不由囤积信息支撑

- **硬约束｜SOURCE-SUPPORTED｜SHR-03、SHR-04、SHR-05：** Rhimes 公开反对为了留故事而把推进放慢，并描述以人物当前所处阶段和季级终点重新发明下一阶段的工作；她把下一季视为需重新回答的创作问题。
- **默认启发式｜SYNTHESIZED INFERENCE｜SHR-03、SHR-04、SHR-05：** 每个 episode 不必制造大 cliffhanger，却应交付至少一项可追踪的状态变化：信息、关系、承诺、职责、资源／限制、目标或未解压力。下集从变化后的状态提问，而不是只把旧问题延长。
- **边界：** 安静、修复、消化或阶段收束也可以是有效变化；“状态变化”不是“事件必须更大”。

### 3. 人物关系与制度世界是供给源，但都不是自动发动机

- **默认启发式｜SOURCE-SUPPORTED｜SHR-02、SHR-06：** Rhimes 的公开材料分别支持：让人物成为推动事情的人；并让 room 规模与分集生产条件相匹配。
- **默认启发式｜SYNTHESIZED INFERENCE｜SHR-02、SHR-04、SHR-05、SHR-06：** 一个稳健的引擎可从以下候选源中取一至数项：
  1. 人物／关系：持续欲望、承诺、信任、权力重分配、冲突性需求；
  2. 职业／组织：职责、程序、资源、层级与反复到来的任务入口；
  3. 环境／未决状态：新信息、长期责任、秘密后果或没有被结清的压力。
- **默认启发式｜SYNTHESIZED INFERENCE：** 每个来源都要通过“会否迫使具体人物做选择、选择会否回流改变状态”的测试。一个职业标签、一个秘密、一次死亡或一次危机本身都不是发动机。

### 4. Pilot 的交付物是“第二集为何自然发生”

- **硬约束｜SYNTHESIZED INFERENCE｜SHR-01、SHR-02、SHR-04、SHR-05：** pilot 结束时必须可验证地建立：世界的运作条件、人物的即时欲望、关键关系／职责、当前核心冲突、至少一个可再生故事来源，以及“EP02 会因 EP01 后状态而不同”的理由。
- **默认启发式｜SOURCE-SUPPORTED｜SHR-02：** ensemble 不是角色清单；角色应彼此构成可说出真相、挑战主角、暴露价值判断或迫使行动的位置。Rhimes 的公开课预览强调人物应“发生于事情”，而非只让事情发生在人物身上。
- **边界：** pilot 无须讲完世界的全部过去，也不必许诺固定 ABC 或以悬崖收尾；未知必须会影响下一步选择，不能只是空的谜盒。

### 5. Episode Engine 与 Season Engine 是不同尺度的同一回路

- **默认启发式｜SYNTHESIZED INFERENCE｜SHR-03、SHR-04、SHR-05：** Episode Engine 回答“本集为何存在”：从上集状态和当前压力中，选择本集最值得推进的一项问题，使它经由人物选择变为新状态。Season Engine 回答“这一组集数要抵达哪个关系、责任、身份或世界状态”，并让每集的变化积累为阶段推进。
- **条件适用方法｜SYNTHESIZED INFERENCE｜SHR-04、SHR-07：** 季级工作可先持有一个终点／目标状态，也应允许表演或叙事理解上的新输入迫使 room 重审路径；预设方向不是不可改的神谕。
- **边界：** 终局方向不是规定每一场、每一集的全部转折；变化也不等于每集加码。

### 6. A/B/C 是编排工具，不是线数配额

- **条件适用方法｜SYNTHESIZED INFERENCE｜SHR-04、SHR-05：** 当一条主线不足以同时承载人物、关系或职业压力时，可用 A/B/C 线安排注意力、节奏、主题对照或关系回响。每条被保留的线应有独立的状态变化，且能与整体产生因果或情感价值。
- **决策门槛：** 若单线已经完整推进状态，不为凑 ABC 加线；若支线只复述主题、只介绍设定或不改变任何选择集，应合并、延后或删除。
- **证据边界：** 未找到可核验的一手材料证明 Rhimes 主张固定 A/B/C 条数，故任何固定条数规则都不属于本蒸馏。

### 7. Continuing Drive 是可解释的下一步，不是廉价钩子

- **默认启发式｜SYNTHESIZED INFERENCE｜SHR-03、SHR-04、SHR-05：** 继续观看的理由可以是新问题、未完成欲望、新信息、关系位置变化、责任后果、资源限制或尚未处理的压力。它应使下一步选择更具体，而不必是更吵、更危险或更大规模的事件。
- **硬约束｜SOURCE-SUPPORTED｜SHR-03：** 若创作只因“还要多做几集／一季”而保留故事、拖慢或重复，Rhimes 的公开做法提供了明确反例：应把已储存的故事写出来，而非把未使用素材当续航本身。
- **默认启发式｜SYNTHESIZED INFERENCE｜SHR-03、SHR-05：** 故事写尽后的下一阶段，应从已经改变的状态重新发明，而非靠人为扣留信息。

## 工作流程

下表是 **可选工具｜SYNTHESIZED INFERENCE**：用已验证的公开做法转译为 AI Film Studio 的 input → judgment → decision → output 回路；工具名不是 Rhimes 的原生术语。

| 阶段 | 输入 | 判断 | 决策 | 输出 |
|---|---|---|---|---|
| 1. 格式与前提检查 | 一句话 premise、预计体量、终点假设、可用世界 | 它是一次性问题、有限故事，还是可产生多轮选择的系统？ | 选择电影／限定剧／连续剧等合适尺度；不强行扩容 | `Format Fit Note` + `Premise / Engine` 分离说明 |
| 2. Engine Map | 人物欲望、关系、职责／组织、环境限制、未解压力 | 哪些输入在 pilot 异常事件之后仍能迫使选择？ | 保留可再生供给源；标注一次性素材与薄弱环 | `Engine Map` |
| 3. Pilot 验收 | 世界、人物、关系、初始冲突、可再生来源 | EP02 是否能明确面对一个经 EP01 改变过的状态？ | 补足关系／职责／选择接口，或降级为非连续形式 | `Why EP02` 测试答案 |
| 4. Season 定向 | 本季起止状态、现实约束、可修订终点假设 | 目标状态是否由已有压力和人物选择可抵达？ | 定义阶段而非硬塞事件；标记需要验证的假设 | `Season State Map` |
| 5. Episode break | 上集新状态、当集资源、候选压力与人物选择 | 本集为何存在？它是推进还是拖延？是否需多线？ | 选择一个主要状态变化；按需要保留／合并／删除 A/B/C | `Question → Choice → New State` 板 |
| 6. 复盘与重破 | 初稿、表演、研究／事实、制作限制、反馈中的困惑 | 新输入是否改变可信选择或既定路径？ | 先诊断问题，再由创作团队提出重写方案；必要时重排 | 更新后的状态账本与下集问题 |

## 诊断问题

1. 如果删除一次性开场事件，是否仍有至少一个人物—关系／职责—压力回路能逼出下一次选择？
2. 这个构想的自然终点在哪里？预计体量与可讲状态的容量匹配吗？
3. pilot 后，谁知道了什么、欠了什么、承诺了什么、失去了什么或获得了什么，使 EP02 不能原样重来？
4. 本集的 A 线是否已经足够承载真实变化？若加 B/C，它们各自改变的状态和服务的节奏／主题／关系是什么？
5. 本季的目标状态是什么？它是人物和压力可抵达的工作假设，还是为了预订数量硬填的事件表？
6. 当前的“继续看”理由是可解释的选择后果，还是只有悬念音效、信息扣留或更大事故？
7. 当前冲突是否仅更换外皮，而人物关系、信息、责任、资源与选择后果均未改变？若是，是否已耗竭？
8. 是否让人物做了不可信的事，只为把剧拖到下一集／下一季？
9. 收到“看不懂／不成立”的反馈时，团队是否定位具体困惑，而非接受他人代写的解决方案？【SHR-07】
10. room 中是否有能提出不同观点的作者，而不是只验证既定答案？【SHR-03、SHR-05】

## 失败模式

| 失败模式 | 可见信号 | 分类错误 |
|---|---|---|
| 把 premise 当 engine | 只能复述开场谜题／世界观，答不出 EP02 | 缺少硬约束 |
| 为集数扩容 | 同一冲突反复延后，人物不合理地不行动 | 违背格式容量与反拖延判断 |
| 事件替代选择 | 每集靠外来事故重启，事件未改变人物责任链 | 把供给源误当发动机 |
| 固定 ABC 配额 | 支线无状态变化，只切换镜头 | 把条件工具误成硬约束 |
| 假 cliffhanger | 结尾藏信息但不会改变下集人物选择 | 把观看刺激误成 Continuing Drive |
| 无限升级 | 每集必须更大，导致因果和人物可信度坍塌 | 把个人节奏偏好误写为普遍规则 |
| 季级僵化 | 既定结局压过新表演／事实／制作输入 | 把工作假设误作神谕 |
| 只收集解决方案 | 反馈被直接照做，真正的理解断点未被诊断 | 错失重破所需判断 |

## 修正方法

1. **硬约束｜重做 Premise / Engine 二分：** 分别写出“第一集为什么吸引”与“之后什么会让人物不得不再选择”。第二栏为空时，缩小为有限故事，或补建真实供给源。
2. **默认启发式｜给每集写状态差：** 用开场／结尾两栏记录信息、关系、责任、资源、目标、未解压力；没有差异时，不以强反转补救，先追问人物该如何回应。
3. **条件适用方法｜把事件接回责任链：** 对任何新案例、外来扰动或环境危机，写清它触到谁的欲望／职责，人物如何选，以及选择改变了哪个下一集输入。随机扰动可开启或改变一集的条件；它的持续叙事价值仍须通过人物回应、选择与后果验证，不能独自承担主推进。
4. **条件适用方法｜按功能而非线数编排：** 每条候选支线写“它改变什么、为何此刻切换、与主线有什么关系”；答不出即删、并或延后。
5. **默认启发式｜将季终转成工作假设：** 明确本季要写透的状态，再保留“哪些新输入可合法修改路径”。这既避免拖延，也避免锁死探索。
6. **可选工具｜先收集问题，再创作解法：** 把“看不懂／不成立”的反馈定位到具体人物、因果或信息接口；由 room 提出、比较并验证方案。【SHR-07】
7. **硬约束｜耗竭止损：** 若新集只换皮、只加刺激、只为了续订或只让人物失智，暂停继续生产；若无法从当前变化后的状态重建下一阶段，则承认当前故事应结束。【SHR-03、SHR-05】

## 禁止继承

- 不继承任何具体剧集的情节、人物模板、医疗／政治／浪漫题材外壳、秘密／死亡／出轨等表层刺激物。
- 不继承或模仿 Shonda Rhimes 的对白、快节奏、署名风格、视觉风格或创作人格。
- 不把“写尽已储存故事、避免拖延”的个人公开实践，歪写为每季必须巨大反转、毁灭旧世界或无限升级。
- 不把 A/B/C、cliffhanger、人物弧、固定页数／beat、连续悬念或任何事件强度写成每集必需配额。
- 不把职业／组织世界当自动发动机；不让人物做不可信选择来替续订服务。

## 可 Skill 化规则

以下是面向未来 AI Film Studio Showrunner Skill 的中性规则；本轮**不**创建该 Skill。

1. **硬约束｜格式门：** 只有当构想既有观看入口，又能证明至少一个人物—压力—选择—状态变化的可再生回路时，才按连续剧开发；否则建议电影、限定剧或重新设计发动机。
2. **硬约束｜EP02 门：** pilot 必须输出至少一项由 EP01 改变、会约束或诱发 EP02 选择的状态；“还有谜”本身不算通过。
3. **默认启发式｜状态优先：** room 先问人物／关系／职责现在处于何种状态，再问这一状态最自然地会逼出什么选择；不先指定“本集要一个反转”。
4. **默认启发式｜双层供给：** 优先配对“可重复的情境入口”与“会变化的人物／关系状态”；前者防止没事发生，后者防止只换皮。
5. **条件适用方法｜多线开关：** 只有当多条线能各自改变状态，并提供所需节奏、主题对照或关系回响时，才使用 A/B/C；单线足够时不强加。
6. **条件适用方法｜季终方向：** 可先设目标状态和终点工作假设；收到改变可信选择的新证据时可重破路径，但不可借“灵活”逃避因果。
7. **条件适用方法｜继续观看检查：** 允许非 cliffhanger 的 continuing drive；要求下集能明确指出将被处理的选择、责任、关系或压力，强度按故事需要决定。
8. **可选工具｜Engine Map：** 对每个供给源标注触发人物、可产生的选择、可能后果与耗竭风险。
9. **可选工具｜State Ledger：** 每集更新人物、关系、信息、责任、资源／限制和未解压力；用于区分推进与拖延。
10. **可选工具｜Room Challenge Pass：** 指派一位作者反问“这是不是只在囤牌／凑线／拖集数？”；不要求共识，要求可解释的反驳。

### 原创可执行性干跑｜通过（独立审查）

**测试概念（仅用于方法验证，不开发为项目）：** 一家小型私家侦探机构处理城市失踪人口档案。三位核心成员各接不同失踪案，同时各自隐瞒一件与事务所创立有关的旧案秘密。

| 检验项 | 干跑结果 |
|---|---|
| Engine 与实际 Engine | “失踪案＋秘密”只是 premise；实际 engine 是案件职责持续触及三人的知情、互信、授权与创立旧案责任，每次处理方式都会改变下一轮选择集。 |
| EP02／03／04 | EP01 的隐瞒可改变办案授权与同伴信任；EP02 从受损信任／授权继续，EP03 从另一成员回应与职责冲突继续，EP04 从累积信息、关系与责任逼出处理旧案的选择。因果来自状态回流，不靠强行反转。 |
| Pilot 与三类供给 | pilot 可建立事务所／城市档案入口、三人欲望与职责、旧案压力，并交付 EP01 后知情／信任／授权状态。供给源分别是组织性档案入口、人物／关系分歧、环境／偶发条件变化。 |
| 长线、单集线与 ABC | 长线为创立旧案、合伙关系、信誉／职责；单集线为各档案的处理。只要单集结果回流长线，就不是换皮案件。可用一条案件线加一条关系线；三线不是配额。 |
| 非大 cliffhanger 的继续驱动 | 授权受限、同伴掌握影响合作的不完整信息、事务所新增责任，都能构成下集可处理的选择，无须灾难性结尾。 |
| 耗竭与归因 | 若新档案不再改变关系、知情、责任、资源或旧案压力，或三人持续做不可信隐瞒来延长秘密，即属耗竭。若发动机存在但 pilot 未交付状态差，是当前结构问题；若案件入口从不触及人物关系／职责，是故事本身缺少 engine。 |

**干跑边界：** 随机扰动可开启或改变一集条件，安静／修复段和单线集均可成立；连续性要求是人物回应、选择与后果可解释，而非每集升级、反转或 cliffhanger。
