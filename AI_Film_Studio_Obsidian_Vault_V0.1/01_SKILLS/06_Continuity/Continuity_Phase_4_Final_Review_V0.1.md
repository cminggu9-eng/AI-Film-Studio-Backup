## Architecture

- Capability Stack: nine evidence-derived layers, from evidence/fact foundation through state reference.
- Decision Flow: evidence → relevant state → context/transition/exception → outcome → materiality → owner handoff.
- Authority Model: cross-department checker, never owner or precedence engine.
- Source of Truth: authority awareness and conflict routing, not Runtime precedence.
- Context Sufficiency: minimum necessary context; no context hunger.

## Fact / State Model

The model formally distinguishes LOCKED FACT, CURRENT STATE, CHARACTER KNOWLEDGE, CHARACTER BELIEF, CHARACTER CLAIM, AUDIENCE KNOWLEDGE, DESIGN/PERFORMANCE INTERPRETATION, MISSING INFORMATION, AMBIGUOUS INFORMATION, AUTHORIZED OR SUPPORTED CHANGE, INTENTIONAL DISCONTINUITY, and CONTRADICTION.

Character claims, belief, suspicion, deception, dramatic irony, and audience exposure are not automatically Canon or character knowledge.

## Continuity Judgment Model

The model covers fact consistency, knowledge legality, information timing, time/order, causality, state transition, spatial/presence, object/appearance/physical state, performance-state awareness, contradiction detection, uncertainty, intentional discontinuity, state snapshot logic, materiality filter, and owner routing.

Primary capability outcomes are mutually exclusive: CONTINUITY PRESERVED; AUTHORIZED OR SUPPORTED CHANGE; INTENTIONAL DISCONTINUITY; CONTEXT INSUFFICIENT; POTENTIAL CONTRADICTION; CONFIRMED CONTRADICTION. They are capability vocabulary, not Runtime tokens.

No canonical Modes are defined: CHECK/COMPARE/DIAGNOSE remain decision-flow activities, avoiding premature dispatch contract design.

## Inputs / Outputs

- Input Model: required material/relevant prior state/available authority; useful direct context; optional broader context only when necessary.
- Output Model: minimum sufficient evidence, comparison, judgment, transition basis, uncertainty, materiality, owner, and handoff.
- Handoff: evidence/context/owner only; never a repair instruction.
