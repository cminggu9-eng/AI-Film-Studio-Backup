# Tony Gilroy｜Showrunner 能力蒸馏 V0.1

> 本稿遵循 `huashu-nuwa` 的直接人物路径与多源提炼，但按 AI Film Studio 管线将研究文件留在 `runtime/_STAGING/_research/Tony_Gilroy_V0.1/`，不创建独立 Showrunner Skill。
>
> 证据标签必须严格区分：`SOURCE-SUPPORTED` 是一手材料直接支持；`SYNTHESIZED INFERENCE` 是跨来源归纳；`AI FILM STUDIO SYNTHESIS` 是本 Studio 为生产与审核建立的规则，不是 Tony Gilroy 的观点。方法分类另标为硬约束、默认启发式、条件适用方法或可选工具。

## 蒸馏目标

提取可复用的 **Reality-Constrained Longform Design（现实约束下的长篇设计）**：在终点意识、场景现实状态、因果现实、复杂信息、模块化长篇、人物—系统摩擦与制作约束之间建立可执行的 showrunner 判断回路。

本稿不提取 *Andor*、*Rogue One*、*Michael Clayton* 的具体剧情、角色、世界观、帝国／反抗军结构、政治惊悚表层、对白、视觉设计或写实主义人格。目标是管理复杂性，而不是模仿表层。

## 核心判断原则

### 1. Destination Awareness：终点清楚，路径开放

- **默认启发式｜SOURCE-SUPPORTED｜TG-01、TG-03、TG-05、TG-06：** Gilroy 多次直接谈到写到结尾、知道要抵达的位置、用终点减少无效扩写；这支持阶段目的和终点意识，而不是所有中间细节一开始锁死。
- **SYNTHESIZED INFERENCE｜默认启发式：** 先写可验证的终点状态、必须成立的因果条件和不可违背的方向，再保留多个中间路径；每个新模块问“是否让终点更有因果支撑”，不是“是否更大”。
- **SYNTHESIZED INFERENCE｜硬约束：** 当项目已进入长篇场景链或模块拆解，却无法说出当前阶段要抵达什么，暂停扩写并重新定向；这不是要求预先写完整剧情。

### 2. Reality State：场景要有可追踪的现实接口

- **默认启发式｜SOURCE-SUPPORTED｜TG-01、TG-02：** Gilroy 将场景“对作者真实”、空间／物理条件、人物当下欲望与进入场景的可见入口视为写作能否推进的诊断。
- **SYNTHESIZED INFERENCE｜默认启发式：** 用 `Scene Entry State → Event / Choice → Exit State` 记录：进入时每人知道什么、想要什么、有什么权限／资源、承担什么风险；事件后谁获得／失去信息、资源、关系位置或策略，下一场因此改变什么。
- **SYNTHESIZED INFERENCE｜硬约束：** 对有因果承载作用的场景，入口和出口必须可解释；不要求每场巨大转折，定位、观察、等待、准备或微小权限变化也可构成有效出口。

### 3. Causal Reality / Reality Check：世界必须回应行为

- **默认启发式｜SYNTHESIZED INFERENCE｜TG-01、TG-02、TG-04、TG-05：** 对关键行为检查：人物是否拥有信息、权限、资源和时间；空间／物理条件是否允许；机构、同事、监管或其他知情者会如何反应；行为的现实后果是否回流下一步。
- **边界｜SOURCE-SUPPORTED｜条件适用方法：** Gilroy 的“现实”讨论支持逻辑、人物行为、空间与因果自洽，不支持禁绝巧合、戏剧化或人物异常决定。人物可以突破规则，但世界必须合理回应。
- **SYNTHESIZED INFERENCE｜硬约束：** 不允许用“编剧想让它发生”替代权限路径和组织反应；不允许把现实检查变成纪录片式绝对写实。

### 4. Complex Story Simplification：复杂不等于混乱

- **默认启发式｜SYNTHESIZED INFERENCE｜TG-01、TG-03、TG-04、TG-06：** 复杂信息按观众当前任务分层：先让人物目标、可见行动、规则与后果可追踪；关键知识要有持有者、获得路径和回报；可延迟的信息必须在后续产生理解或戏剧收益。
- **SOURCE-SUPPORTED｜默认启发式：** Gilroy 直接讨论“谁知道什么、如何得知”、观众为信息花费的注意力，以及删掉会夺走核心内容的混乱；这不等于要求观众立即理解全部世界。
- **SYNTHESIZED INFERENCE｜条件适用方法：** 解释、行动、物件、空间和人物目标都可承载复杂信息；选择哪种载体取决于当前因果负荷和观众需要完成的任务。

### 5. Modular Longform Structure：模块是容器，不是配额

- **SOURCE-SUPPORTED｜默认启发式｜TG-02、TG-03、TG-06：** Gilroy 直接描述过 block、阶段、局部可处理单元、story conference 与模块首尾验证；同时说明制作安排会影响 block，不能为了容器强迫故事。
- **SYNTHESIZED INFERENCE｜默认启发式：** 每个 block／chapter／phase 应有局部问题、局部状态变化、阶段输出、遗留压力和交给下一模块的资源／信息／关系；长度由故事、平台、时间与生产条件决定。
- **SYNTHESIZED INFERENCE｜条件适用方法：** 可按制作 block、时间跨度、人物阶段目标或信息压力组织模块；不得硬编码“三集一个 block”、每模块同构或每集都承担整个季的功能。

### 6. Character Within Systems：人物欲望与系统摩擦

- **SOURCE-SUPPORTED｜默认启发式｜TG-01、TG-02、TG-04、TG-05：** Gilroy 直接把人物欲望、选择、知识和行动放在机构规则、资源、空间与社会系统中讨论；人物不是脱离系统的剧情工具。
- **SYNTHESIZED INFERENCE｜默认启发式：** 为每个主要人物记录欲望、权限、依赖、制度风险、地理／时间限制、可用资源与组织回应；人物选择改变系统，系统反过来改变下一轮可行选择集。
- **边界｜SYNTHESIZED INFERENCE｜条件适用方法：** 本模块只提取人物—系统的窄范围工作法，不代替 David Simon 的 World-System 蒸馏。

### 7. Production Reality Check：先保留戏剧价值，再重设计执行

- **SOURCE-SUPPORTED｜默认启发式｜TG-02、TG-03、TG-06：** Gilroy 直接谈过制作设计、规模、预算可承受性、地点／时间限制、系统化前置准备，以及限制如何逼出替代解法；他没有提出本稿的固定术语或数量阈值。
- **AI FILM STUDIO SYNTHESIS｜硬约束：** 本 Studio 采用 `Creative Intent → Production Cost Driver → Must Preserve → Can Redesign → Alternate Execution → New Risks`。任何“太贵所以删掉”但没有戏剧价值分析的处理都不通过。
- **AI FILM STUDIO SYNTHESIS｜可选工具：** 记录角色数、地点数、群演、车辆、动作、特效、时间／地理跨度与连戏风险；这些字段是制作审查工具，不得归因给 Gilroy。

### 8. Scope Compression：压缩外壳，不抹掉核心关系

- **SOURCE-SUPPORTED｜条件适用方法：** TG-02、TG-06 支持限制与制作规模可以促成新的结构方案；没有直接证据表明 Gilroy 提出“Scope Compression”名称或固定顺序。
- **AI FILM STUDIO SYNTHESIS｜条件适用方法：** 先识别权力关系、调查压力、危险升级、人物选择与世界规模感的戏剧价值，再合并角色／地点、缩小行动视角、压缩时间跨度、复用空间或改写执行方式；保留功能，不保留昂贵外壳。
- **AI FILM STUDIO SYNTHESIS｜条件适用方法｜边界：** 低成本不是自动优先级；若压缩后失去核心创意意图、因果链或人物系统摩擦，应退回重设计。

## 工作流程

以下为 `SYNTHESIZED INFERENCE｜可选工具` 与 `AI FILM STUDIO SYNTHESIS｜可选工具` 的组合工作流；不是声称 Gilroy 使用过完全相同的表格或术语。

| 阶段 | 输入 | 判断 | 决策 | 输出 |
|---|---|---|---|---|
| 1. Destination Card | 当前 premise、目标状态、终点条件、可变路径、未知 | 是否有足够明确的方向，又保留发现空间？ | 锁定阶段目的／不可违背条件；保留中间候选 | `Destination Card` |
| 2. Reality State Card | 场景入口的知识、欲望、权限、资源、风险与空间 | 哪些条件允许事件发生？事件会改变什么？ | 设计可解释的 event／choice；删掉无因果入口 | `Entry → Event → Exit` |
| 3. Causal Reality Gate | 信息路径、时间、机构规则、资源、系统反应 | 行为是否可执行？异常决定的世界后果是什么？ | 保留、补路径、改权限、改场景或重写回应 | `Reality Check` |
| 4. Complexity Pass | 人物／机构／地点／规则／观众当前任务 | 现在必须知道什么，什么可通过行动推断，什么可延迟？ | 调整呈现层级；删除不改变目标与选择的解释 | `Knowledge / Goal / Access / Consequence` |
| 5. Modular Story Conference | 阶段终点、已有 beats、缺口、制作边界 | 模块完成什么局部状态？如何把压力交接？ | 共同 beat out、补缺口、分工、允许重排 | `Module Map` + `Handoff Debt` |
| 6. Production Reality Check | 创意意图、角色／地点／群演／动作／特效规模 | 哪些是成本驱动，哪些是不可丢失的戏剧功能？ | 重新设计执行，不直接删创意 | `Alternate Execution` + `New Risks` |
| 7. Rough-Cut / Feedback Pass | 草稿、排演、粗剪、部门反馈、观众信息负荷 | 混乱是否夺走核心内容？出口状态是否仍可追踪？ | 删减、ADR、重排、补路径或保留有目的留白 | 修订后的状态账本与模块交接 |

## 诊断问题

1. 当前阶段要抵达的可验证状态是什么？哪些只是可探索路径？
2. 若提前知道终点，是否仍允许中间路径改变、发现与删改？若不知道终点，哪些内容正在无方向膨胀？
3. 进入场景时，每个人知道什么、想要什么、能做什么、怕失去什么？
4. 离开场景后，谁获得／失去信息、权限、资源、关系位置或策略？若没有大变化，场景是否仍完成了定位、观察、准备或必要等待？
5. 人物是否拥有完成行为所需的信息、权限、时间和资源？
6. 机构、同事、监管、家人或其他知情者会如何合理回应？
7. 观众当前必须知道什么，什么可以通过目标／行动／后果推断，什么可延迟且会有回报？
8. 当前 block 的局部问题、局部闭环、遗留压力和下一模块接收物是什么？为何不是固定三集？
9. 这个人物的欲望怎样与等级、法律、资源、地理、时间和系统摩擦？
10. 制作规模中真正的创意价值是什么？哪些是成本驱动因素？替代执行是否保留核心关系、压力、危险和世界感？
11. 当前“继续观看”承诺来自因果、人物选择、信息回报还是廉价悬念？
12. 是否把复杂写成不透明，或把现实写成禁绝巧合与异常决定？

## 失败模式

| 失败模式 | 信号 | 修正方向 |
|---|---|---|
| 终点空缺 | 大量前期搭建无法筛选，模块互相漂移 | 补当前阶段终点与不可违背条件；开放路径 |
| 终点锁死 | 每个过程节点都被预定，发现与人物选择失效 | 只锁目标状态与因果条件，恢复候选路径 |
| 场景无入口／出口 | 人物突然出现，事件后状态等同进入前 | 补 Entry State、权限路径和 Exit State；允许小变化 |
| 编剧强行发生 | 角色突然知道无权获取的信息，机构没有反应 | 追溯权限、时间、资源、空间和组织回应 |
| 复杂等于解释 | 大段背景说明，观众仍不知道谁要什么 | 以人物目标和行动承载信息，删除非目标负荷 |
| 复杂等于故弄玄虚 | 信息延迟没有目标、路径或回报 | 明确持有者、获取路径与兑现时点 |
| 模块配额化 | 固定三集、每块同构、局部故事服务模板 | 由阶段问题和生产条件重新划块 |
| 人物脱离系统 | 主角不受权限、法律、资源和时间限制 | 更新系统关系图，写出世界回应 |
| 制作优先删创意 | “太贵，删掉”成为唯一方案 | 使用 Creative Intent → Cost Driver → Alternate Execution |
| 现实主义禁令 | 禁绝巧合、戏剧化和异常决定 | 保留选择自由，补可信后果 |

## 修正方法

1. **SYNTHESIZED INFERENCE｜硬约束｜Destination Repair：** 写出当前阶段必须抵达的状态与因果条件，再列出足够比较的一个或多个可变路径；删除不能服务方向的素材，不锁死中间事件。
2. **SYNTHESIZED INFERENCE｜硬约束｜Scene State Repair：** 为关键场景补 Entry State、Event／Choice、Exit State；如果出口没有大变化，说明它的定位／准备／观察功能，不用强行加反转。
3. **SYNTHESIZED INFERENCE｜硬约束｜Reality Repair：** 对异常行为建立信息、权限、时间、资源和组织回应链；不能通过“碰巧拿到秘密文件”跳过权限路径。
4. **SYNTHESIZED INFERENCE｜默认启发式｜Complexity Repair：** 给每条信息标持有者、获取路径、当前目标价值和回报时点；将解释改写为行动、规则、空间或后果。
5. **SYNTHESIZED INFERENCE｜条件适用方法｜Module Repair：** 依阶段压力、人物关系、时间跨度和生产条件重划模块；每块交付局部状态与遗留债务，不追求固定长度。
6. **SYNTHESIZED INFERENCE｜默认启发式｜System Repair：** 为人物补权限、依赖、制度风险、地理／时间限制与资源；让系统回应选择，而不是把系统当背景。
7. **AI FILM STUDIO SYNTHESIS｜Production Repair：** 先写核心戏剧功能和成本驱动，再给至少一个 Alternate Execution 与新风险；不得直接删掉昂贵场面而不解释保留价值。
8. **AI FILM STUDIO SYNTHESIS｜Scope Repair：** 优先压缩地点、角色、群演、车辆、移动、动作和时间跨度的外壳；若权力关系、调查压力、危险升级或世界规模感消失，回退方案。

## 禁止继承

- 不继承任何具体作品的情节、角色、星战世界观、帝国／反抗军模板或政治惊悚套路。
- 不模仿 Tony Gilroy 的对白、视觉设计、写实审美或创作人格。
- 不把“知道结尾”写成锁死全部过程；不把“现实”写成禁绝巧合、戏剧化或人物犯错。
- 不要求每场巨大变化、每集大反转、每段动作爆炸性 hook 或固定三集 block。
- 不把复杂写成观众必须迷失，也不以大量解释替代目标、行动和后果。
- 不把制作成本置于创意价值之前；不把 Scope Compression 或 Production Reality Check 伪写成 Gilroy 的固定术语或算法。
- 不提前完成 David Simon 的 World-System 能力蒸馏；本稿仅保留人物与系统摩擦的窄范围。

## 可 Skill 化规则

1. **SYNTHESIZED INFERENCE｜硬约束｜Destination Gate：** 开始长篇模块化之前，必须写出当前阶段终点状态、因果条件和至少一条可变路径；未满足则停止扩写并重定向。
2. **SYNTHESIZED INFERENCE｜硬约束｜Reality Gate：** 关键行为必须有可追踪的信息、权限、资源、时间与组织回应；异常行为可以通过，但世界后果必须存在。
3. **SYNTHESIZED INFERENCE｜硬约束｜Scene State Gate：** 关键场景必须能描述 Entry State、Event／Choice 与 Exit State；不要求巨大变化，但不能完全无功能地重复入口。
4. **SYNTHESIZED INFERENCE｜默认启发式｜Knowledge Layer：** 先由人物目标和可见行动承载复杂信息，再决定哪些解释、留白或延迟值得保留。
5. **SYNTHESIZED INFERENCE｜条件适用方法｜Module Switch：** 只有当局部问题、阶段输出和交接压力清晰时才拆 block／chapter／phase；长度和数量由项目决定。
6. **SYNTHESIZED INFERENCE｜默认启发式｜System Friction：** 每个主要人物记录欲望、权限、依赖、制度风险、资源与世界回应；用选择改变下一轮可行集合。
7. **AI FILM STUDIO SYNTHESIS｜硬约束｜Production Switch：** 每个高成本创意先填写 Creative Intent、Cost Driver、Must Preserve、Can Redesign、Alternate Execution、New Risks；缺任何关键字段不得删创意。
8. **AI FILM STUDIO SYNTHESIS｜条件适用方法｜Scope Switch：** 压缩地点／角色／群演／动作／时间跨度前，必须列出保留的权力关系、调查压力、危险升级、人物因果与世界规模感。
9. **AI FILM STUDIO SYNTHESIS｜可选工具｜Room Conference Board：** 记录终点、beats、缺口、模块责任、制作限制和待回收问题；工具不取代判断，也不要求复制 Gilroy 的人员配置。
10. **AI FILM STUDIO SYNTHESIS｜可选工具｜Audience Calories Pass：** 标记观众正在为哪个信息负荷付出注意力；删除或重排抢走核心内容的混乱，但保留有目标、有回报的复杂性。

### 原创可执行性干跑｜PASS（独立复测）

测试概念：沿海城市大型物流企业系统升级后，旧货运记录被人为修改；普通内部审计员追查出物流企业、地方承包商与重要港口建设项目之间的长期利益关系。

独立测试结果（原创概念，不形成正式项目）：

1. **Destination：** 阶段终点设为“审计链条完成可核验的记录时间线，并把正式调查决定交给合规／监管接口”；必须提前知道记录链、权限边界与决定点，调查路径可在 IT 日志、工单、采购与监管之间改变。
2. **Reality State：** Entry：审计员只被指派财务异常，拥有系统审计权限但没有备份、迁移日志或承包商档案权限；Event：以记录 ID、时间缺口和升级工单向直属主管提出正式查询；Exit：主管批准、限缩、延迟或转交请求，改变审计员的权限、期限与职业风险。
3. **Complexity：** 显性层为异常、升级、审计与主管；延迟层为历史版本、管理员身份、迁移日志、承包商工单、采购与港口交叉记录；压力层为运营截止、项目进度、法律／监管、职业声誉。
4. **Modules：** 第一阶段依次为异常基线与记录封存 → 权限申请与主管决策 → 追查迁移日志／工单 → 建立利益关系图并交合规／监管；每块都有局部闭环和交接压力，不规定集数。
5. **Causal Reality：** 审计系统权限允许提出正式请求，主管回应决定下一步，IT／管理员日志再开放工单路径，采购记录连接承包商与港口项目；没有“碰巧看到秘密文件”，每次信息都沿权限、时间和组织反应获得。
6. **Production Reality / Scope Compression：** 18 个角色先按功能压缩为审计、IT／迁移、承包商、合规／法律、物流运营、港口权力、监管 7 个叙事接口；14 个地点收束为审计办公室、迁移控制室、承包商／项目办公室、港口现场、政府会议、档案空间；两场大型港口行动可共享地理并保留不同叙事功能，多个政府会议合并为一次关键会议，其余用纪要／视频／授权链表达；车辆与群众以可复用港口空间和受控背景保留世界规模。每项压缩均保留调查压力、权力关系、危险与世界尺度，替代执行后的新风险为信息密度上升、空间重复感和调度可见度下降。

干跑没有要求每场巨大变化、固定三集模块或每步升级；也没有把随机事件绝对禁用，而是要求其后的主要推进由人物回应与现实后果承载。
