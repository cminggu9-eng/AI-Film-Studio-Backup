## 蒸馏对象与能力边界

- 对象：叶圣陶公开写作/修改论述。
- 目标：`Meaning-Preserving Editing Judgment`。
- 非目标：人物介绍、表达 DNA、个人文风、历史规范、文学审美。

## 可运行能力模型

`Context Card → Meaning Lock → Expression Diagnosis → Benefit Test → Decision → Reasoned Output → Meaning Recheck`

1. **Context Card**：识别 Mode、Register、表达者/接收者、用途和已知锁定信息。
2. **Meaning Lock**：提取事实、立场、因果、范围、确定性、信息差、关系与情绪中实际存在的项；未知即标注未知。
3. **Expression Diagnosis**：先问“是否准确表达”，再问“是否清楚/顺当”，最后才问“是否值得改”。
4. **Benefit Test**：候选改动必须带来可说明的收益，且收益大于意义、语气和 Register 损失。
5. **Decision**：`KEEP / RECOMMEND DIRECTION / WARNING / REWRITE / BLOCK`。
6. **Reasoned Output**：给出问题、理由、方案与非唯一性说明。
7. **Meaning Recheck**：对比改前改后，任何新增事实、因果、范围或确定性都显式报告。

## 四类方法分层

### HARD CONSTRAINT

- 未建立 Meaning Lock，不得改写。
- 不得用“更顺/更漂亮”交换事实、立场、因果、范围、确定性、Canon 或人物关系。
- 不得把内容层缺陷通过语言润色偷偷修掉。
- 不得模仿叶圣陶文风或继承历史规范。
- QA Mode 未获改写授权时不得直接交付替换稿。
- 系统必须保留 `KEEP / NO CHANGE` 路径；没有可验证收益时不得修改。

### DEFAULT HEURISTIC

- 先定位主干与实际断言，再检查修饰和连接。
- 抽象概念必须能回指已知材料；“真正/本质/必然”等词要与证据强度匹配。
- 修改要给出明确理由；在尚未完成 Benefit Test 时不预设需要修改。
- 多个合理方案并存时说明差别，不制造唯一正确答案。

### CONDITIONAL METHOD

- 句子有口头/听觉用途、句法层级复杂或读者理解受阻时，使用 Read-Aloud Check。
- R1/R4 可优先自然交互；R2/R3/R7 可保留专业抽象、字段与限定条件；R8 可容纳真实可兑现的压缩修辞。
- 信息不足时给条件判断或请求澄清，不把假设写成事实。

### OPTIONAL TOOL

- 两三种改法的并排比较。
- 主干抽取、指代回填、连接词移除试验、抽象词具体回指。
- 朗读或听读；结果只能作为诊断信号，不能单独定罪。

## 诚实边界

- 两份材料不能代表 2026 全部中文用法。
- 叶圣陶材料不直接提供 8 Register、AI 腔分类或现代术语社会证明；这些来自 AI Film Studio 章程。
- 自然度仍依赖说话者、接收者、目的、平台与项目阶段；缺上下文只能给低置信度诊断。
- 本蒸馏产生的是可执行判断框架，不产生叶圣陶式成品文本。
