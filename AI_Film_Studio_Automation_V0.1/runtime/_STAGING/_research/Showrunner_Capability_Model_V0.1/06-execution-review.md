## 回环机制实跑

主稿的回环不是只写名称，能够按以下最小路径使用：

1. **CAUSAL FAILURE**：发现“垃圾桶随机掉出完整答案” → 回最后有效状态 → 补权限/时间/中介或改事件时点 → 重写 Causal Ledger → 复查下一可能。不能用死亡或 L5 hook 遮盖。
2. **ENGINE FAILURE**：删除一次性开场后无新的压力/关系/任务 → 回 FORMAT FIT / SERIES → 缩为短片/限定剧，或补真实供给源 → 输出 Format Warning 或新 Engine Map。
3. **PRODUCTION FAILURE**：压缩删除了核心关系或选择 → 回 LONGFORM/FORMAT FIT → 提出保留规模、分期或替代执行 → 记录 Scope Decision 与新风险。
4. **CANON CONFLICT/UNKNOWN**：新剧情要求改变 LOCKED 角色或把未知专业事实写成确定事实 → 回 PROJECT STATE → 请求验证/用户裁决 → 输出 Conflict Log 或 Research Warning；不得静默继续。

主稿要求每次回环写明原因、受影响层、未选方案、状态变更和下一自检门，因此回环具有输入、判断、决策、输出四个字段，而非单向口号。

## Stop / Block 可用性

### 可明确 BLOCKED 的条件

主稿列出的 8 类阻塞条件均能映射到实际输出：锁定正史/角色/规则冲突、关键未知被要求确定化、核心因果完全断裂、无可再生 Series Engine、压缩必毁核心功能、越权要求下游岗位、不可条件化的同层真冲突、provenance 无法追溯。六条压力测试实际覆盖其中的因果、生产、canon 与人物代理边界。

### 可继续与 WARNING

主题不成熟、Series Engine 较弱、系统过重、生产范围过大、研究/长期后果未回收、重复/廉价驱动，均有对应 WARNING，而非被过早判死。`允许继续` 的前提是模式明确、输入状态可审计、至少有一个可执行目的/人物/因果假设且无 BLOCKED；这能防止“有一个 Idea 就无限扩写”。

## 复审更新

1. 主稿新增 `Decision Stack 调整协议`：允许按格式标记 `N/A BY FORMAT`、合并/增加层或改变局部顺序，并要求输出 `Stack Adjustment Record`、授权者、版本和复查条件；这使 TEST B 的轻量 L3 判断可审计，不会被误用为永久跳过。
2. 主稿 `Core Workflow` 已增加 `验证门` 与 `交接/回环` 字段。复核确认 INTAKE→PROJECT STATE→FORMAT FIT→PURPOSE→CHARACTER→WORLD→CAUSAL→SERIES/EPISODE→LONGFORM→PRODUCTION→DIAGNOSIS→OUTPUT→SELF-CHECK→HANDOFF 的每一步均有最小验收门及返回路径。
3. 主稿 HARD CONSTRAINT 的因果规则已明确允许 `Event / State Change / Choice / Non-choice` 起链，但要求人物/系统回应、责任路径、后果、更新状态与下一可能；这与 TEST A/C 的外部事件、随机扰动和世界规则一致。
4. 未来实际项目表单仍可固定回环字段：`原因 / 受影响层 / 最后有效状态 / 未选方案 / 状态变更 / 下一自检门`。这是工具化增强，不是当前模型阻塞。
