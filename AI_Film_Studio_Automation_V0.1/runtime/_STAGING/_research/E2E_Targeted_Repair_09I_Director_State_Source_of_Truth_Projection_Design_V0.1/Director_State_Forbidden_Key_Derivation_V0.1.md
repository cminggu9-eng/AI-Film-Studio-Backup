# Director State Forbidden Key Derivation V0.1

Forbidden properties must derive from positive source-schema closure plus role boundaries. Existing contracts already prohibit the five objects from carrying duplicate outer controls/transport data (`selected_mode`, `primary_state_or_outcome`, flags, handoffs, locks, prohibitions, output prose, `scene_packages`) and from taking Showrunner Canon, Acting method, Art Director design, or undeclared production authority.

Because no positive nested property set is closed, a full literal nested forbidden-key registry cannot be derived without invention. The current safe rule is: any nested key not emitted by the future approved deterministic projection is forbidden; until such a projection exists, no runtime schema is allowed.
