# Director Five State Object Semantic Audit V0.1

## Authority method

Sources were evaluated in the authorized order: Canonical Director Skill; frozen Director/Integration contracts; State Evidence/State Ledger; compiled fixture contracts; acceptance definitions; downstream consumers; then frozen invariants. Probe04, E2E-RUN-13, and E2E-RUN-14 are observed examples only.

| Field | Lawful semantic purpose | Director boundary | Upstream dependency | Downstream consumer | Exact schema result |
|---|---|---|---|---|---|
| `relevant_prior_state` | lawful pre-direction context | may not create Canon or future state | source-attributed prior state/locks | Envelope, Ledger, Continuity | AUTHORITY GAP |
| `current_state` | observable, actionable present snapshot | may not make narrative dump | Scene Writer state and locks | Envelope, Ledger, Continuity | AUTHORITY GAP |
| `proposed_state` | proposed directorial impact, not committed Canon | may not decide Showrunner outcome | authorized transitions and locks | Envelope, Ledger, Continuity | AUTHORITY GAP |
| `knowledge_timing` | preserve authorized audience/character/reveal timing | may not leak or retime knowledge | knowledge events and Scene Writer locks | Envelope, Ledger, Continuity | AUTHORITY GAP |
| `visual_state` | source-attributed visual/spatial continuity input | may not design Art Director solution or performance method | visual state/production constraints | Envelope, Ledger, Continuity | AUTHORITY GAP |

## Why the gap is real

The Canonical Director Skill establishes purpose and authority boundaries, not nested keys. The 09B contract declares the five values as objects (or `ABSENT`) but not their object properties. State Evidence preserves JSON-safe values without object schemas. The fixture compiler derives only Scene Writer scene-package state dimensions, not Director state-object schemas. Therefore no existing authorized source closes properties, requiredness, value types, or token domains for these Director values.

Historical key sets differ: Probe04 includes `key_custody` and a two-key `visual_state`; R13 uses three-key prior/current/proposed objects and per-scene visual keys; R14 adds `source`. These differences demonstrate why example aggregation would be reverse specification.
