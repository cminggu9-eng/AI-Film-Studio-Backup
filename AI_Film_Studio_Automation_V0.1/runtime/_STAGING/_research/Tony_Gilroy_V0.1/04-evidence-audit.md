# Tony Gilroy｜Reality-Constrained Longform Design 证据审计与核心来源账本 V0.1

> 状态：研究区未审核材料；本文件不属于 Obsidian 正式档案，也不是最终蒸馏稿。
>
> 审计目标：建立唯一核心来源账本，区分 Tony Gilroy 本人的可核验陈述、跨来源归纳与 AI Film Studio 自有流程规则。只提取判断方法，不提取具体作品情节、角色模板、对白、视觉风格或政治惊悚表层。

## 1. 证据标签与使用边界

- `SOURCE-SUPPORTED`：来源是 Gilroy 本人的直接访谈／讲座陈述，或官方机构发布的 Gilroy 访谈逐字稿；结论不得超出原文范围。
- `SYNTHESIZED INFERENCE`：至少两份 `SOURCE-SUPPORTED` 材料交叉归纳出的可执行方法；不得写成 Gilroy 原话。
- `AI FILM STUDIO SYNTHESIS`：为本项目的审核、干跑、生产和发布而制定的 Studio 自有规则；不得归因给 Gilroy。

证据强度等级：

- A：Gilroy 本人直接陈述，且载体有可读逐字稿／完整 PDF；可支撑狭义方法判断。
- B：官方机构对 Gilroy 访谈的准确转述，或直接采访中多个段落相互印证；可支撑方向性判断，但不能扩展为普适规则。
- C：二手评论、作品分析、搜索摘要或未能读取全文的页面；只能定位线索，不能单独进入核心账本。

本账本只把 A/B 级来源列为核心材料；未能全文读取的 Script Magazine 页面不列入核心证据，不用其搜索摘要替代原文。

### TG-01｜BAFTA/BFI Screenwriters’ Lecture Series：Tony Gilroy

- URL：<https://static.bafta.org/files/tony-gilroy-lecture-transcript-2058.pdf>
- 日期：2013-09-29；载体为 BAFTA/BFI 官方讲座逐字稿 PDF。
- 一手性：A；Tony Gilroy 本人讲授并回答现场问题，官方逐字稿。
- 可直接支持：
  - 他反复说明应把 outline 写到结尾；知道结尾能提供完整感、减少无效页面，并让前段材料接受删改（PDF pp.5–6）。
  - “每个场景必须对自己真实”是其个人写作自述；卡住时通常是没有把场景看见、没有把它变成可报告的现实（pp.5–6）。
  - 对于较重要角色，要问“这个人想要什么”；复杂行为需要理解矛盾与同理心（p.5）。
  - 其具体破题做法包括角色扮演、假设“如果他做这个，意味着什么”，通过对话和场景反推剧情（p.6）。
  - 共同创作时以口头“spitballing”加速复杂情节；但这描述的是他的工作习惯，不是固定 writers’ room 配方（p.6）。
  - 反复删减不必要台词和说明，令脚本更紧，但不等于每场都要删到同一长度（pp.6–7）。
- 不可外推：
  - 不能直接推出“所有长篇必须知道完整结局”；此处是 Gilroy 对个人 outline 习惯的强烈建议，任务书明确禁止将其机械化成普遍硬规则。
  - 不能从“每个场景真实”推出禁绝巧合、戏剧化或异常人物决定；“真实”是其创作体验与场景可视化标准，不是现实主义题材模板。
  - 不能从“每个重要人物问欲望”推出每场必须让所有人物改变。
  - 不能归因于电视 block、预算压缩或现代 showrunning；讲座主要讨论原创电影剧本。

### TG-02｜WGA East OnWriting Episode 104：Tony Gilroy, “Andor”

- URL：<https://www.wgaeast.org/onwriting/episode-104-tony-gilroy-andor/>
- 日期：页面未显示明确发布日期；内容为官方节目逐字稿，访问核验日期 2026-08-21。节目在第一季播出后讨论剧集制作。
- 一手性：A；Writers Guild of America East 官方播客，主持人直接采访 Tony Gilroy，并公开 transcript。
- 可直接支持：
  - Gilroy 描述先设想长期跨度、不断 sketch，再问一年后想抵达哪里；但他同时说故事并非从一开始就完美排布（transcript lines 264–269）。
  - 12 集和三集 block 的成形与经济、英国拍摄、导演安排和制作 mandate 相关；他明确说不想为了 block 强迫故事，结构是逐步 coalesce（lines 266–269）。
  - 制作设计师 Luke Hull 是他的主要写作伙伴；每个场景都需讨论空间、搭建和能否负担，且已有场景可复用（lines 435–444）。
  - 他以低成本拍摄的车内追逐举例，认为动作价值来自人物在行动中的真实问题，而不是花费规模（lines 396–397）。
  - 他把角色、行为与逻辑视为核心关注，创作中会检查角色权限、既有规则与世界内事实是否连贯（lines 318–322、391 附近）。
- 不可外推：
  - 三集不是通用结构单位；来源明确表明 block 受导演和制作安排影响，且不愿强迫故事。
  - 不能把“与生产设计师共写”扩展为每个项目都必须让某类部门成为共同作者。
  - 不能把“低成本车内戏有效”推导为低成本优先，或删去大型动作；只能支撑戏剧问题应先于花费规模的局部判断。
  - 这是针对一部具体剧集的创作回顾，不能把作品世界或政治主题当成方法论。

## 4. 重要边界：哪些只能标为推断或 Studio 自有规则

### 4.1 `SYNTHESIZED INFERENCE`

- “Destination Awareness”是跨来源归纳名，不是 Gilroy 在这些来源中使用的固定术语。允许表达为：从他对 outline 结尾、已知最终位置、模块 proof of concept 的多次陈述归纳出的工作法。
- “Entry State→Event→Exit State”是 AI Film Studio 为检查场景状态变化建立的抽象，不是 Gilroy 直接提出的公式。只能标为跨来源归纳后的工具化表达。
- “复杂性简化”不是把世界删成简单；它是从他关于角色欲望、信息知晓差异、具体空间限制和删减的陈述归纳出来的呈现策略。
- “人物—系统”是将其关于逻辑、角色决定、限制和系统回应的材料合并后的方法模块；不要写成 Gilroy 宣称的理论名称。
- “剧情链耗竭”可由其批评重复周常任务缺少 story nutrients 支持，但“耗竭判定表”本身是 Studio 的操作化工具。

### 4.2 `AI FILM STUDIO SYNTHESIS`

- `Creative Intent → Production Cost Driver → Must Preserve → Redesign → Alternate Execution` 是本项目的制作审查协议，不是 Gilroy 原话。
- Scope Compression 的目标字段、压缩顺序、18 角色／14 地点／大型行动的干跑格式，均为本项目用于可执行性检查的自有设计。
- 最终稿中的“输入 → 判断 → 决策 → 输出”模板、风险分级、证据标签和发布门槛是管线规则，不得归因于 Gilroy。

## 5. 证据冲突与解释

### 冲突 A：知道结尾 vs 允许发现

- TG-01/TG-05/TG-06 强调知道结尾、知道最终位置能减少浪费并产生模块解法。
- TG-02 说故事逐步演化，未完美铺排；TG-06 说模块方案来自问题中的发现，且通过 sketch 和 proof of concept 验证。
- 审计结论：不存在真正矛盾。应拆成两层：
  1. 阶段目的／终点意识清晰，避免无方向扩写；
  2. 中间路径、场景次序、交接方案允许试探、重排和意外发现。
- 禁止写法：“全剧所有细节必须预先知道”；推荐写法：“在当前阶段明确足够的目的地和不可违背约束，保留路径发现并允许重排”。

### 冲突 B：模块化 block vs 反对强迫 block

- TG-02 明确三集 block 与拍摄、导演和经济条件有关，且不想强迫故事。
- TG-03/TG-06 说明 block 作为局部闭合和长跨度压缩的有效方案。
- 审计结论：block 是条件适用的结构容器，不是硬规则。审核重点应是模块的功能、局部代价、交接和生产可行性，而不是集数。

### 冲突 C：限制是朋友 vs 成本不应主导创意

- TG-06 直接称限制会逼出更好的解法；TG-02 说明空间和可负担性进入设计讨论。
- 这不能推出“预算优先”。来源中的限制是围绕既有故事问题寻找 alternate solve，且仍以人物问题、空间逻辑和戏剧价值为中心。
- 审计结论：制作现实检查必须保留创意意图；若只因昂贵而删掉核心关系／危险／权力结构，应判定为错误压缩。

### 冲突 D：每场“真实” vs 不要求每场巨大变化

- TG-01 的“每场真实”是场景可视化、可进入、可报告的创作标准。
- 它不等于每场都要反转、升级或让所有状态大幅变化。现实场景可以完成定位、准备、观察、误判、等待或微小权限变化。
- 审计结论：将“真实”解释为可追踪输入、事件和出口条件；不得机械化为“大变化”。

## 6. 反机械化检查清单

- [x] 不把“知道结尾”写成所有创作细节必须锁死。
- [x] 不把三集 block 写成固定集数，不把“serial films”写成所有剧集必须电影化。
- [x] 不要求每场巨大状态变化、每集大反转或每段动作都有爆炸性 hook。
- [x] 不用世界观名词、组织模板、角色姓名、台词或视觉风格作为证据。
- [x] 不把复杂性等同于信息隐藏；隐藏信息必须让人物目标、行动和权限关系仍可追踪。
- [x] 不把现实逻辑等同于禁绝巧合、戏剧化或人物犯错；世界需要对异常行为作出可信回应。
- [x] 不把“限制是朋友”改成成本优先；必须先写创意意图和不可丢失的戏剧价值。
- [x] 不把 Gilroy 的个人写作习惯伪装为普遍 showrunner 规范。
- [x] 所有 production/scope compression 规则均标 `AI FILM STUDIO SYNTHESIS`，除非后续找到直接一手证据支撑更窄的归因。

## 7. 对原创干跑的证据边界建议

测试概念：沿海大型物流企业系统升级后旧货运记录被篡改，普通内部审计员追查出企业、地方承包商与港口建设项目的利益关系。

干跑可以使用下列来源支持的判断框架，但故事内容必须是原创，不得套用任何被访谈作品：

1. **Destination Awareness**（`SYNTHESIZED INFERENCE`）：先定义第一阶段要抵达的可验证状态，例如审计员获得一条可核验的权限链；允许中间路径发现。
2. **Scene State**（`AI FILM STUDIO SYNTHESIS`）：测试“审计员向主管询问异常记录”时，记录进入前的权限／信息／风险，询问事件，以及问完后主管权限、审计员风险和可用资源的变化。
3. **Complexity Layering**（`SYNTHESIZED INFERENCE`）：先让读者跟随审计员的目标和可见记录，再逐层揭示承包商、港口项目和制度反应，不以解释堆积替代行动。
4. **Modular Phase 1**（`SYNTHESIZED INFERENCE`）：以局部问题闭合并把新权限／新风险交给下一模块；不得预设三集。
5. **Reality Check**（`SYNTHESIZED INFERENCE`）：核验审计员能查什么、主管能遮什么、系统日志谁能改、承包商如何回应，以及异常行为的组织后果。
6. **Production Reality Check / Scope Compression**（`AI FILM STUDIO SYNTHESIS`）：面对 18 角色、14 地点、两场大型港口行动、多个政府会议和车辆群众，先标出创意意图和成本驱动，再决定合并角色／地点、把会议变成有权力后果的单一接口、缩小行动视角或重写为可控替代执行；不得直接删除调查压力、权力关系和危险升级。
